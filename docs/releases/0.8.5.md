# v0.8.5 — One order per export, and no more stuck saves

Fixes for three rarer ways an export could go wrong: ordering your medical file twice, a save that never finished, and a large upload that kept pausing the run. It now needs Chrome 120 or newer.

> [!NOTE]
> Unofficial. Not affiliated with, endorsed by or sponsored by Maccabi Healthcare Services.

## What's fixed

- **One medical file order per export.** If Maccabi's answer to the order was lost, or Maccabi took the order without sending an SMS, an export that reconnected afterwards could order again, and text you again. Now an order that went out is never sent again in the same export. And when Maccabi takes the order without texting you, the export waits for that file instead of keeping the previous one.
- **A save that can't get stuck.** If Chrome closed while the ZIP was downloading, the popup could stay on "Saving" for good, with no way to cancel or start a new export. Now it says the ZIP wasn't saved and offers **Save again**, which builds the ZIP from the files already collected.
- **Large uploads finish.** A document you uploaded to Maccabi that took more than a minute to download, on a slow connection, read as an ended session, and the export paused at the same file every time you pressed **Resume**. Now a download gives up only after a minute with nothing arriving. An upload over 32 MB is listed as a problem instead, and the rest of the export finishes.
- **Less memory after a failed save.** A ZIP that didn't save no longer stays in memory beside the next one.

## What's changed

- **Chrome 120 or newer is needed** (it was 116), so the export checks on itself every half minute, as it was meant to.

The export's files and layout are the same as in 0.8.4, so an export paused on 0.8.4 resumes after the update.

## Install or update

You need Chrome 120 or newer.

**[Install from the Chrome Web Store](https://chromewebstore.google.com/detail/lmjcbhajlnbpldofejcglcdclceampjp)** and Chrome keeps it up to date — though store review can lag a day or two behind a release here.

To load this ZIP unpacked instead:

1. Download **health-records-export-for-maccabi-0.8.5.zip** from the assets below and unzip it.
2. Open `chrome://extensions` and turn on **Developer mode**.
3. Click **Load unpacked** and select the unzipped folder, the one with `manifest.json` in it. Keep that folder: Chrome loads the extension from it.

Updating from an earlier version: unzip over the old folder, or load the new one and remove the old entry, then press the reload arrow on `chrome://extensions`. An export in progress won't survive the swap — finish or stop it first.

Then [export your records](https://github.com/RoniRachmani/health-records-export-for-maccabi/blob/v0.8.5/README.md#export-your-records), and [see what to ask your AI assistant](https://maccabi.ronirachmani.com/#ask). The code isn't minified, so you can read exactly what runs.

## Before you start

- **Maccabi will text you.** Each export orders a fresh copy of your medical file, which sends an SMS and replaces the previous file on the site. It's the only change the extension makes to your account.
- **Keep the Maccabi Online tab in front** until the export finishes. Chrome pauses hidden tabs.
- **If your session ends,** log in again and press **Resume**. The files collected so far are kept.

## Privacy

- Talks only to `online.maccabi4u.co.il`. No servers, no analytics, no remote code.
- Never sees your password or one-time codes. It uses the session you're already logged in with.
- Apart from ordering the medical file, it only reads. Every request it makes is listed in [docs/endpoints.json](https://github.com/RoniRachmani/health-records-export-for-maccabi/blob/v0.8.5/docs/endpoints.json).
- **The extension sends your records nowhere, but an AI service you open them in can read them.** Check what it keeps, and for how long, before you give it your health information.
- **The ZIP isn't encrypted.** It holds your health information: keep it somewhere safe, and take care when you share it.
